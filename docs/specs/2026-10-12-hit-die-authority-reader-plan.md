## Proposed serialization barrier and writer participation

**Technical choice for independent challenge:** one protected transaction-owned row `private.character_writer_guard_v1(singleton=true)` as a coarse mechanical/shared-write mutex. This trades throughput for a small auditable protocol at first beta; no external queue/service/advisory-key collision. All reviewed mechanical/shared/lifecycle entrypoints acquire it before character/shared/child DML. With every affecting writer participating, it protects absent membership/share/grant/ref rows and newly inserted dependencies as well as existing rows; an empty SELECT cannot do that. Later partitioning is a separate measured change.

Order: audited auth user/session/profile prefix where required; writer guard; affected character IDs sorted; shared rows in documented table/ID order; refs/grants/inventory/spells/receipts/rolls by stable keys. Mutation wrappers discover the affected identity set before the guard and recheck it after acquisition; changed owner/affected-set means reject/retry the same bounded intent before mutation, never silently acquire new earlier-order locks. Profile deletion begins inside Auth, with auth/profile locks already held; its private lifecycle trigger must take the guard before public dependency/child changes. G2 must prove the provider's actual auth/session/profile order matches this prefix. A row trigger acquired after a child or parent is locked cannot establish the protocol; legacy functions that lock first are replaced/denied at cutover. No SKIP LOCKED, no lock retained across REST requests.

Statement-level guards on affecting public tables reject DML outside the audited writer/lifecycle function-owner roles; they are backstops, not substitutes for entrypoint ordering. Membership in those roles is never granted to browser/service callers, and no caller-set GUC/session marker authenticates a writer. Functions get exact bounded operations and immutable search_path; broad direct mechanical table/column/child privileges and old definer signatures are removed in one separately reviewed activation transaction only after all adapters/client paths work. Deployment/superusers remain trusted operational authority. Installation/ACLs are atomic; schema USAGE only, no runtime CREATE.

Readiness ledger records exact schema/protocol version plus reviewed function/trigger/ACL signatures for each writer family; runtime caller cannot mark ready. Resolve/commit checks readiness under guard. A default-false or missing family is unavailable, not optional; merely adding a revision column or trigger cannot certify a fence. Every semantic mechanical mutation advances affected character revision monotonically in the same transaction (including child inserts/deletes/reparenting, materialization/pruning, owner/campaign/system/archive changes); no-op adapters do not advance it. Shared rule/access changes also serialize and are reprojected/compared even if a parent revision did not change. Copy starts a fresh revision domain and never copies action operation IDs/accepted rolls/receipts.
