builder character. The saved version grants expanded spells automatically;
the corrected version makes earned expanded spells ordinary candidates within
the existing allowance. **No spell is automatically learned by the update.**

Opening or cancelling review writes no character, receipt, capability, history,

## Preview and confirmation contract

The account/character-bound server preview accepts only an old subclass-ref UUID
and target version. It freshly verifies the current signed-in account and asks
`character_builder_subclass_update_preview_v1` for an authoritative descriptor.
The response contains its actor/character, exact update fields, saved/target
names, finite named consequences and `automatic_spells_learned: 0`.

`update_subclass_version` uses the existing ordinary retained-intent protocol.
Its fields bind the Warlock occurrence, exact old ref/content/version, target
version, expected action revision and SHA256 preview digest. The transaction
checks a matching historical receipt before stale-preview/version checks, then
rederives the descriptor under the existing guard/parent/source locks. Changed
ownership, source, revision, old ref, occurrence, dependency closure or preview
must refuse atomically. After an accepted receipt, a changed request cannot
reuse its operation ID.

Only the old Fiend source closure changes. Unrelated classes/occurrences,
controller identities, choices, ordinary spell selections, base scores,
HP/state/draws, ASI provenance, inventory/currency and unrelated row identities
must remain exact. Former free grants are removed, never converted into known
selections. If the sealed compiler cannot preserve these supported domains,
the update refuses rather than silently resetting them.

Confirmation always uses the boundary's existing terminal reload sequence:
validate the exact receipt, clear that exact account-scoped pending record,
unmount editor guards/portals and reload current server values. Lost-response
check/retry reuses the original operation and never reapplies a historical
choices snapshot over current state.

A stale review without a receipt can be released only by the dedicated

Only an enrolled character whose native action revision is strictly greater
