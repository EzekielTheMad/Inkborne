# Native Fiend correction boundary

This staged companion installs after `character-builder-expanded-spells.sql`
and `character-builder-class-removal.sql`. It changes no hosted target, catalog
snapshot or activation gate. It supports only the existing genuine native,
uncampaigned builder cohort. Class/race/legacy-origin repinning remains refused.

The explicit `update_subclass_version` request carries the owning occurrence,
old subclass ref/content/version, chosen higher current version, expected parent
revision and native preview digest. The preview RPC verifies the actual signed
actor/session through `begin_builder_step_v1`, takes the shared guard and parent
lock, and returns a finite display summary without writing a capability or row.
The digest binds the full parent/graph/order, raw old/new root snapshots, complete
feature and spell dependency snapshots, and displayed consequences. Generated
projection UUIDs are allocated only during confirmation.

This first policy accepts only the genuine ten-spell Fiend list moving from
`spellcastingExtra` to `spellcastingExpanded`. The old and new tiers must match;
all other root data/effects/identity must be unchanged. A newer root timestamp
must resolve the identical feature dependency closure. Features with choice or
bonus-spell machinery are outside this policy. Existing free grants are shown as
removed; earned expanded candidates are shown as available, with zero automatic
ordinary spells learned. Existing ordinary selections remain exact.

Confirmation authenticates and locks again. Existing exact receipts replay
before source/revision checks. Otherwise the command recomputes and compares the
complete preview fields. It uses the existing finite `select_subclass` compiler
and capability to materialize only the reviewed subclass closure. The retained
request/receipt command stays `update_subclass_version`; its append-only native
history records both graph/order snapshots. No acquisition proof is relabelled.
Unrelated rows, choices, class occurrence identity, class-role profiles, base
scores, state/HP, level, inventory and awards must remain exact or the transaction
rolls back. The subclass ref and its owned manifest/projection IDs may change.

A same-slug version update leaves parent choices identical. Three private
capability fields bind the original correction operation, preview digest and
one-time revision consumption. A closed helper reads only the current-xid sealed
before/expected graph and exact immutable root pair. The existing revision
trigger receives one additional finite condition; its first-acquisition,
metadata, ordinary mechanics, exhaustion and manual-revision refusal branches
remain byte-preserved. Its owner, ACL and attributes remain unchanged. The native
`+1` and existing order-rebind producer handle the revision; no fake choice marker
or caller-assigned revision is introduced. Final invariants additionally require
the bridge consumed and exactly one revision, closing the ordinary mechanics
condition's short-circuit path.

The read-only full-original resolution RPC returns an accepted exact receipt
first. When no receipt exists, only a strictly larger observed database-owned
revision in the locked genuine cohort proves that the exact original review is
permanently stale. Its strict rejection proof binds actor, character, operation,
command, raw fields, `stale_review` reason and observed revision. This is neither
UUID cancellation nor a durable UUID reservation. Bare absence, unavailable
catalogs and transport failures remain uncertain. The official client clears
only a matching stored intent under its current account lease and generates a
fresh UUID for a fresh review. This makes authoritative stale review recoverable
without discarding an unknown operation.

Installer preflights pin exact existing compiler, finish and command bodies.
The revision trigger goes from MD5 `2daf275513b60cc98818f07a7e982946` to
`857950f1a88305838220494f068e5cf5` with owner/ACL/config/volatility preserved.
New public functions grant execution only to authenticated callers and still
verify the actual actor/session. New private helper execution stays owner-only,
except the revision helper's single internal grant to the existing revision
authority. Service-role private-schema usage remains closed.

Focused PGlite vectors execute the new descriptor/wrapper/revision profile with
explicit Auth and graph-writer doubles. A separate vector executes the complete
real installer against actual admitted historical function bodies, including its
pre/post profile and ACL checks. These are not native JWT/compiler/concurrency or
browser acceptance. The disposable real application must separately prove old
v1 publication, explicit v2 preview/confirmation, foreign/stale refusal, accepted
receipt recovery, exact preserved rows/HP, and repeated reload stability before
this slice is accepted. General writer/copy/access/lifecycle fences stay open.
