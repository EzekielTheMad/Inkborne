## Full manifest and tuple closure

For every class/subclass controller pin, validate actual shared content schema, unique selected controller occurrence and same character/system immutable tuple. Class slug is its pinned slug; subclass parent class must be nonblank and match one selected pinned class plus its selected subclass. The first supported profile requires these selected controllers; unselected/ambiguous legacy controller rows remain unavailable. Inactive means future unlock within a supported selected controller, not permission to discard provenance.

Interpret only `spellcastingExtra`, the shipped class/subclass materializer's input. Absent key means no entries; present JSON null/nonarray/malformed means unavailable. Do not reinterpret feature/feat/item `spellcastingExtra` or bonus spell-list access as frozen always-prepared grants. Accept these supported native schema formats without modifying their raw JSON: scalar spell string at one-based outer ordinal; array of spell strings at that ordinal; subclass object `{level:number integer1..20,spells:string[]}`. SQL permits some broader object representations; digit-string levels/class object tiers and other unsupported shapes remain unavailable until parser policy is separately approved. Unknown raw extension keys survive in the snapshot; they are not authority inputs. Blank/invalid/nontext entries are unavailable. Trim only U+0020 at each end, matching default PostgreSQL `btrim`, not JavaScript Unicode `.trim()`. Nonempty implicit tiers beyond level20 are unsupported. Empty tiers contribute no grant and must not turn an invalid nonempty tier into an empty success.

Normalize an expected map keyed `(controller_ref_id, normalized_spell_slug)`, preserving first encounter only for bookkeeping and coalescing duplicates to minimum unlock. For **every** expected key require exactly one raw grant; reject missing, extra or duplicate keys/IDs. SRD controller requires frozen spell source SRD and platform scope. Homebrew controller source must be supported and uses preserved frozen lineage, not today's content access to choose a replacement.

Do **not** rerun the historical candidate ORDER BY or current access lookup on read. ## Activity, representative and acquisition closure

Compute activity from persisted `choices.classes` and exact controller selection/parent class, with selected class level `>= unlock_level`. Retain all inactive raw grants and validate their manifest tuples as above. Choose one active representative per `(spell_content_id,class_slug)` using the shipped order: lowest unlock level, then PostgreSQL UUID order of controller_ref_id, then grant ID. Implement UUID ordering by canonical UUID bytes/hex, not locale collation. Result metadata can be ordered by content UUID/class slug for assertion; never reorder pins/grants/spells or use this representative ordering as mechanical source ordering. Class-slug collation is irrelevant to choosing the within-group representative; grouping uses exact strings.

The adjacent acquisition schema requires present nullable `spell_grant_id` and supported source. This child supports `selection` and `feature`; `feat`, `item` or unknown sources remain `unsupported_spell_profile` until their own earned-source closure exists. That is a bounded authority profile, not a removal/migration of existing product rows.

For `feature`: require nonnull active representative grant ID, exact character/content ID/version/class/name tuple, both preparation flags true, exact immutable resolved spell. Reject inactive/nonrepresentative/spoofed/duplicate links and any custom-null identity. For `selection`: require null grant ID; preserve its exact stored acquisition/version/name/preparation/known/spellbook fields. Pinned selections use their own exact immutable spell version; custom selections require content ID/version/resolved all null and null grant ID. Custom spells never satisfy a frozen representative's content identity.

Enforce physical uniqueness of nonnull `(content_id,class_slug)` consistent with the existing unique index. For each active representative require exactly one corresponding physical acquisition. It may be its exact derived feature row or an existing selection of that content ID/class, even at a different version. Selection precedence changes only the logical preparation overlay, never its saved identity/version/name/source or preparation bytes on read. No missing acquisition is repaired by the reader. A missing row, stale feature row after level change, or conflicting duplicate is incomplete/unavailable until an explicit separately fenced reconciliation succeeds. Losing the selected row and installing the grant's physical row occurs only in the existing authorized writer transaction, never a validator side effect.

The helper returns representative IDs for verification only. It does not call `applyActiveSpellGrantOverlays`, mutate S or hand a manufactured complete grant projection to another consumer. No arithmetic leaf model can certify the actual graph.
