## Proposed additive data contract

Use the existing field family on subclasses, with strict subclass requirements rather than class defaults: optional nullable `spellcasting` config; optional `spellcastingKnown`, `spellcastingList`, `spellcastingExtra`; optional nullable `levels[].spellcasting` rows. Reuse primitive validation constraints, not class validators that insert default focus/ritual/prepared/row values. New optional fields preserve raw absence; every declared non-null profile must supply its required fields. Keep feature rows, `spells`, description and grant payloads intact. No migration or automatic historical-data rewrite.

For a **new non-null subclass casting profile**, require declared ability/type/focus/ritual flag; known mode (`prepared` explicitly boolean), a complete twenty-level cantrip series and spells-known series or `"all"`; a typed list class/range; and the selected unique numbered slot row. Do not default missing readiness fields, prepared mode, config or rows. Slot rows require nine finite nonnegative integers. If optional row `cantrips_known` also exists, it must agree with the selected known-series count; disagreement is unavailable. Array series are explicitly class levels1–20; progression rows remain identified by their `level`, never array index. Finite/integer validation applies at runtime as well as schema boundaries.

Prepared subclass profiles must explicitly declare a bounded `preparation_rule` alongside their profile: `class-level-plus-ability` or `half-class-level-plus-ability`, both with the existing minimum-one behavior. Required only when `prepared: true`; no parent-slug guess or arbitrary formula support. Known subclass profiles use no prepared capacity. Parent prepared casters retain their current rule/behavior. This small additive enum is a decision for challenge; rejecting unsupported prepared subclass profiles is preferable to inventing their capacity.

Freeze an **additive subclass grant validator**: optional `spellcastingExtra` is an array whose entries accept (a) a nonblank slug string, (b) an array of nonblank slug strings, or (c) a tier object with an explicitly declared finite integer `level`1–20 and explicitly declared `spells` array of nonblank slug strings. Empty spell arrays remain valid; missing object level/spells, whitespace-only slugs and wrong types fail. Preserve valid tiers/order/slug values rather than flattening, sorting, defaulting unlock levels or rewriting immutable payloads. The object branch must not be replaced by the current shared `spellcastingExtraSchema`; use a subclass-specific `subclassSpellcastingExtraSchema` union, leaving the existing shared/class validator untouched and preserving existing grant behavior. SQL remains unchanged.

Both `spellcastingExtra` and legacy top-level `spells` are **excluded from casting-profile markers**, regardless of their contents. They remain grant/display metadata handled by existing immutable capture/reconciliation; neither proves a new caster, known/prepared mode, slot row nor free-cast payment. Casting-profile markers are config, known/list profile, preparation rule or a declared row's casting field. Recognize existing known/list fields rather than discarding them, so legacy partial casting profiles cannot masquerade as ordinary inheritance.

## Frozen precedence and compatibility proposal

Always validate the exact selected parent pin and its explicit unique selected level row first. If a subclass is selected, require exactly one readable subclass pin with matching character/system/content/version/type/slug and `parent_class`; use **parent class level**, never total character level. Missing, duplicate, malformed or mismatched selected refs are unavailable; another author's readable pin is permitted. Unselected/stale subclass refs cannot supply casting.

| Readable selected evidence | Effective source / behavior |
| --- | --- |
| No subclass selected; valid parent evidence | Existing parent behavior unchanged. Missing parent rows/config still unavailable. |
| Subclass has no casting-profile markers (including feature-only, object-tier grant-only, legacy `spells`, or their combination), or explicit `spellcasting: null` with no active/partial casting rows or known/list profile | Inherit validated parent profile, including its explicit inactive row. No subclass casting row is required at the current class level: feature/grant rows may be sparse. This is **no subclass override**, not parser-manufactured subclass inactivity. Ordinary legacy noncasting subclasses and shipped full/half/Pact parents keep working. |
| Subclass lacks config but has known/list or row casting-profile markers; profile fields omitted/malformed; a casting profile's selected subclass row is missing/duplicate | Unavailable. Never infer third casting, ability, unlock or counts from a slug, seed label, list or total level. The selected subclass casting-row requirement applies only when a subclass casting profile is declared, never to a grant-only subclass. |
| Parent config is explicitly null **and** parent selected row is explicitly null; subclass complete non-null profile with selected row null | Valid inactive class source. No caster controls or contribution at this class level; rest remains usable. |
| Same explicitly noncasting parent; complete subclass profile with selected non-null valid row | One active source under parent slug; subclass config/counts/list/row supply mechanics. Non-null zero-slot/cantrip-only rows remain active. |
| Parent declares any casting config and subclass declares its own non-null casting config | Unavailable unsupported dual profile, even if one selected row is null. Do not merge abilities, replace a parent caster silently, or count both. Ordinary subclass grant-only additions do not enter this case. |
| Config null but row claims slots; explicit null mixed with known/list/active-row markers; conflicting counts | Unavailable inconsistent evidence. |

The compatibility rule is additive opt-in: absence of every **casting-profile marker**, excluding grants/legacy spells, leaves the existing parent contract intact. Presence of any casting-profile marker requires complete proof. Tests must exercise raw immutable snapshot parsing to demonstrate absence remains absent and object-tier grants remain readable without manufactured casting fields/rows. Legacy partial third-caster seeds remain unavailable until a separately authorized lawful author supplies a complete pinned profile; this child neither backfills nor accepts named book content.

## One resolved source graph and consumers

Add a pure available/unavailable effective-source resolution from stored choices and exact refs. Each class entry carries parent pin, selected subclass pin when present, class level, active/inactive state, provider kind (class/subclass), declared casting config, known/preparation/list metadata and selected direct row. There is at most one active entry per parent class. Parent-only metadata retains shipped compatibility semantics; strict new subclass fields do not silently broaden old parent validation.

1. Slots consume this graph: one active regular source uses its own row; multiple regular classes retain R21.1a weighted multiclass arithmetic. Pact stays separate with count/level from one validated row and existing ambiguity rejection. Subclass identity contributes no extra class level/source. Keep bounded large-pool rendering.
2. Provider derives casterInfo and preparation/count display from the same graph. Unavailable graph status propagates to tracker, add/cast, recovery/rest and print with existing reload/content guidance. Preserve degraded loaded spell display; do not call unknown an accepted zero pool or present an invented profile. Valid inactive/noncaster/zero-slot cases can rest.
3. R21.1b acquisition resolution chooses the entry by the loaded acquisition's **parent** class slug, retaining exact spell identity and loaded snapshot precedence. It resolves subclass ability with the same unique system ability/finite math checks. Extend the committed-source guard to subclass pin/profile changes; old callbacks reject even with identical raw state. Do not change computeCastEffects, state writer or roll receipts.
4. Add/search uses the effective list class/range and that source's direct highest learnable level (intersect the declared range), while new acquisition payload keeps the parent class slug. Casting/upcasting still uses the shared pool. Known/cantrip caps and prepared mode follow the effective source, not the stronger class's aggregate slots. Provider add execution requires a currently available selected source; UI search is not server authority or a replacement for existing DAL ownership/content rules. Keep viewer mutations blocked through existing role/DAL boundaries.
5. Print uses each effective parent-class ability/counts and includes its existing exact subclass pin; global highest summary remains explicitly labeled. Parent hit dice/HP/armor/resources remain unchanged. Arcane Recovery still scales from its existing pinned feature's declared class (Wizard when omitted), preserving explicit homebrew reskins. A subclass using the Wizard list does not become a Wizard or gain Recovery.
