# R21.1a — selected-source spell slots

Base: `9ae5a656a7636442fd1d2767b3013ca9a43ec26b`. Local implementation only; no migration, dependency changes, content authoring or permission changes.

One `SlotResolution` now determines regular slots and independent Pact Magic count/level from the selected exact class snapshots. Every selected class needs a readable matching character/system/content/version pin, valid casting profile and a unique explicit selected level row. A null row is inactive; a nonnull all-zero/cantrip row is an active source. Slot rows must contain nine finite nonnegative integers. Sparse/reordered numbered progressions are supported; missing/duplicate/invalid evidence is unavailable, with no index-derived tags or fallback mechanics.

Exactly one active regular source uses its own row, fixing single Paladin/Ranger progression (for example level 3 has three first-level slots). Multiple active regular sources retain the existing weighted multiclass calculation. Noncasting and Pact Magic sources do not force regular multiclass progression. Pact uses its validated type, including original custom class names; count and level come from the same row, and multiple populated levels/sources are unavailable.

The provider exposes the result; existing `maxSlots`/`pactSlotLevel` aliases remain for caller compatibility and are guarded by that result. Cast actions, slot editing, rest execution, recovery eligibility, spell addition/search and printing refuse unavailable evidence. Actual controls show reload/content-recovery guidance. Both whole short and long rests are blocked while unavailable because their existing atomic patches include slot restoration. A valid noncaster or zero pool remains available and can rest normally. Existing Arcane Recovery and conditional state writer are reused.

Focused fixtures use the actual class schema and original private progressions: full/half/custom-third, early custom unlock, typed custom Pact with one regular source, two regular sources, null versus active zero rows, sparse/reordered rows, bad numbers/counts/tags/levels/duplicates and missing/foreign/mismatched pins. Actual provider tests exercise tracker, cast, rest and print guards; existing conditional short-rest and Recovery tests receive explicit original pinned class rows. The prior isolated print renderer fixtures supply explicit available resolution metadata; those remain renderer fixtures, not provider parity evidence.

Validation: focused `npm.cmd test -- ...` covered 16 files / 329 distinct tests, green across the initial run and targeted fixture repairs; final provider/rest guards passed 2 files / 40 tests. After browser fixture refinements, the four affected real-provider suites passed together (64 tests). Final `npm.cmd run typecheck`, `npm.cmd run lint` and `git diff --check` pass. The first run's eight failures were test-fixture mistakes (an accidental expected-RPC field and an inaccessible stacked-modal query); lint then caught an empty-object test type and a probe assignment during render, both repaired and verified. Locked `npm.cmd ci --ignore-scripts` completed its process; Next installed is 16.3.8. No server or live database/provider access was started. Process metadata is in ignored `test-results/r21-slots`. Parent owns the final combined check/build.

`npm.cmd run test:e2e -- --config e2e/slots/playwright.config.ts`: four cases pass (3.5 seconds), all four final screenshots visually inspected. The harness bundles actual CharacterProvider/controls, uses explicit original pinned rows with in-memory conditional persistence, and denies provider-client access. Half caster and custom Pact plus one regular source agree across tracker, printable values and cast payments; unavailable content blocks rest/print without writes; valid noncaster rest heals normally. It does not substitute context hooks. It omits compiled application Tailwind and includes minimal dialog positioning CSS, so it establishes bounded mechanics/control behavior rather than full styled application UAT, complete rules parity or hosted persistence/permissions. Initial browser failures exposed fixture omissions (game-system metadata, raw persisted state, and dialog layout); these were fixed without changing the product implementation. Owned test/browser processes and descendants were verified gone; no task port was opened.

Limits: this child does not enable subclass casting profiles, per-class attack/DC correction, Arcanum/Mastery/Signature payments or third-caster source content. It does not repair unreadable historical pins automatically or validate existing legacy spent-slot keys. Those boundaries remain in the R21.1 inventory. Hosted permission/manifest/state acceptance remains separate from local source and simulated-provider validation.
