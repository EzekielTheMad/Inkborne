Planning base: `85f8ee9`, isolated `r21-ability-worker`, branch `codex/r21-source-casting-ability`. No implementation, dependency installation or test/browser/build process has started. **Outcome:** a spell acquired under a weaker casting class must use that class's attack bonus/save DC even when another class has a stronger ability. The same spell content/version acquired under two classes has two distinct casting profiles. Unknown, stale or unreadable sources cannot fall back to the global best.

## Proposed implementation contract

1. Add a pure source-ability resolver, preferably `lib/spells/casting-ability.ts`, and an available/unavailable result. An available result contains acquisition/class pin identity and one mathematical profile (`classSlug`, ability slug, ability modifier, attack bonus, save DC). An unavailable result contains concise reload/content-recovery guidance and no borrowed numeric values.
2. At the provider boundary, resolve the target by its acquisition **row id** in the current loaded spell list. Require one row and matching target character/content/version/class identity; reject a foreign row, missing acquisition, duplicate row or stale/caller-modified source identity. Use the current loaded row's snapshot for effects and profile resolution. This prevents a supplied copy from silently choosing a stronger class. No new query or current-catalog lookup.
3. Require a unique matching selected class choice and readable exact class ref: character/system/content/version/type must match, and its selected numbered casting row must be active. Reuse R21.1a validation rather than guessing unlocks or treating omitted data as inactivity. Null/inactive rows, duplicate classes/refs, malformed profiles and unsupported sources are unavailable. Spell acquisition must have a matching readable exact **spell** snapshot in the same character/system. Do not require snapshot author equals viewer.
4. The declared casting ability must identify an ability in this system schema, with a finite evaluated score. Require a finite evaluated proficiency bonus. Preserve the current known-source formula `floor((evaluatedScore - 10) / 2)` and the existing attack/DC helpers' arithmetic; no new modifier/buff interpretation or raw defaults for missing evidence. Valid-source damage/healing `MOD` substitution keeps that same modifier. Unsupported custom/no-snapshot spells remain unavailable, consistent with today's `castSourceFromCharacterSpell`; this child does not add their casting mode.
5. Expose the resolver through `useSpells` so preview and provider execution share the same result. A viewer may inspect a readable resolved profile, but Cast remains disabled for read-only viewers. Provider execution checks owner/read-only, slot resolution and current acquisition/source resolution **before** entering the existing conditional action. A rejection produces no state write or roll. Preserve pending, stale-render, conflict/uncertain and failed-save behavior; no new state writer or mutation tracker.
6. Replace `computeCastEffects`' mathematical reliance on `casterInfo`/optional `classSlug` with a **required explicit resolved casting profile**. Attack, DC and MOD consume it; remove the best-mod fallback from this computation. Keep cantrip scaling, slot/pact/ritual payment, concentration/effect patching, crit behavior and roll metadata/persistence paths unchanged. Pure computation is not an authorization boundary: the provider validates acquisition/pin authority; the static importer passes an explicitly synthetic profile with its existing numbers. The only importer edit is this call adapter and removal of obsolete local scaffolding if unused.
7. CastDialog shows the acquisition's class/ability and its resolved attack/DC. On unavailable evidence show recovery guidance, omit numeric claims and disable execution for all cast modes. Preserve existing spell damage/healing lookup/upcast previews; resolve MOD display consistently if showing its numeric value. Keep `casterInfo` for existing preparation/ritual/count behavior. Retain SpellHeader's global highest values and explicitly label the multiclass summary as highest class DC/attack; each cast uses its own source. No subclass schema, advanced/free-cast selection or learning-rule rewrite.
