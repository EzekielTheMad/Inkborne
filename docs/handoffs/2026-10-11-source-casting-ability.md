## Result and boundaries

`resolveCastingAbility` binds the requested acquisition id to exactly one current loaded row, validates character/content/version/class identity, then uses that loaded snapshot rather than caller-supplied data/effects. It requires the exact readable selected class pin and active numbered row through R21.1a, one system ability slug, finite evaluated score/proficiency and finite computed modifier/attack/DC. Missing/ambiguous/inactive/foreign-character/foreign-system/mismatched pins have explicit unavailable guidance and no numeric fallback. Readable foreign-author historical pins remain valid; no catalog query, author-equals-viewer check, SQL or policy change.

Provider execution guards owner status, slot availability, acquisition/profile availability and committed React casting-input identity. An old callback is rejected after acquisitions/snapshots, class pins/choices, schema ability definitions, evaluated ability/proficiency or viewer status change even when raw state is unchanged. Existing pending/current-state/conditional-save safeguards remain. This is a local React freshness check; it does not prove cross-session acquisition freshness or server-side authority. R09's hosted/server freshness and runtime acceptance limitations still apply.

The pure cast calculation now requires explicit source math. Attack/DC and damage/healing `MOD` use the same class ability. CastDialog shares that resolution, shows class/ability and hides numeric claims for unavailable sources; viewers can inspect but cannot execute. SpellHeader retains its highest-class values and labels the multiclass summary. Preparation, ritual eligibility, normal/Pact payments, cantrip scaling, concentration/effect patches, roll metadata and persistence remain. MPMB supplies its same explicitly synthetic +3 MOD/+5 attack/DC13 profile; no live acquisition is inferred there. Print already lists each class's values and is unchanged.
