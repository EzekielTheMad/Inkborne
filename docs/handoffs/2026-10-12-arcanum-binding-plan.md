### Exact modeled evidence, contributors and usage state

Freeze these three distinct records, never an activity boolean: controller `{refId, characterId, contentId, contentVersion}` plus its raw class/subclass snapshot; captured grant `{grantId, characterId, controllerRefId, featureSlug, featureContentId, featureVersion, unlockLevel}`; derived feature ref `{refId, characterId, featureGrantId, contentId, contentVersion}` plus the original raw feature snapshot. IDs are valid nonempty UUIDs and versions positive integers; each lookup/edge is unique. This is a modeled immutable manifest relation, not a new production RPC response.

All character IDs equal the target; all snapshot systems equal its system; each ref content/version equals its raw snapshot; grant controllerRefId equals that controller ref; derived featureGrantId equals grantId; grant feature content/version equals both derived ref and raw feature; featureSlug equals the raw feature slug. Controller must be the exact **currently selected** parent class ref, or exact currently selected subclass ref paired with that parent. Its content/version agrees with the effective source graph. Feature data.class equals the parent slug. A declared feature subclass must equal a selected subclass controller's slug; conflicting parent/subclass labels are rejected, not normalized.

Controller numbered feature rows must validate explicit integer levels1–20 and feature slug arrays. Captured unlockLevel must equal the earliest explicit numbered row containing that feature slug; it must also equal the feature payload's declared gain level. Duplicate numbered rows or contradictory parent/unlock/feature/version evidence are unavailable. Activity derives from the selected parent class level meeting that validated unlock while the selected controller relation is current. Total character level, descriptor spell level, resource count and names are not unlock evidence. Tests must falsify each tuple equality separately. Production materialization/permission remains server responsibility; later adapters must preserve this tuple rather than inventing missing fields.

Resource collision detection consumes the complete original eligible resource contributors before `computeResources` deduplicates by slug: primary feature/feat/trait resources plus extraLimitedFeatures with their existing slug construction. The candidate uses its feature slug and declared1/long-rest payload. Exactly one contributor may own that state key. Another qualifying feature/feat/trait or extra resource with the same key makes payment unavailable even if the deduplicated list contains one entry or duplicate values agree. Contradictory/malformed contributor identity or unknown completeness must not certify uniqueness. Do not mutate/deduplicate inputs, create a replacement counter, or trust the already-deduplicated resource output as collision proof. Existing unrelated generic-resource rendering remains unchanged.

Usage policy: an absent feature_uses field is an empty map; a present field must be a non-null plain object (not array/string/boolean) whose present values are finite nonnegative integers. Under a valid map, an absent own selected resource key means0. A present null/string/NaN/Infinity/negative/fractional selected key or malformed present map is unavailable, never coerced/defaulted to0. Read own properties; prototype inheritance cannot supply usage. Valid selected usage0 permits selection/payment; usage>=1 is exhausted and unavailable without reset. Missing binding cannot bypass malformed/exhausted state to become unselected. This policy is model-only and does not rewrite historical state or expand generic rest semantics.
