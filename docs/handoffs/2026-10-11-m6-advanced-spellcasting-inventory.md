## Rule and rights boundary

Checked Wizards' official [SRD 5.1 CC-BY PDF](https://www.dndbeyond.com/attachments/39j2li89/SRD5.1-CCBY4.0License.pdf): Paladin/Ranger tables pp. 30/35; multiclass rules pp. 57–58; Arcanum p. 48; Mastery/Signature pp. 53–54. One regular Spellcasting class uses its own progression; multiple such classes use weighted progression, with Pact Magic separate. Arcanum selects one spell at each unlocked level 6–9 (Warlock 11/13/15/17), each free once per long rest. Mastery selects book spells of levels 1/2, requires preparation for free base-level casts, and permits replacement after eight hours' study. Signature selects two book spells of level 3, excludes them from prepared capacity, and gives each one free base-level cast per short/long rest. Mastery/Signature upcasting spends ordinary slots.

EK/AT names are absent from this SRD. Do not import book text or treat the old seed as licensed content. Test generic third-caster schema support with original, privately authored fixtures. Any named non-SRD content needs a separately established lawful source/entitlement boundary.

## Finite implementation sequence

1. **R21.1a — single-source slots.** Own `helpers.ts`, provider slot DTO adapter and related tests only. Count active regular Spellcasting sources by class, excluding Pact/noncasters and classes below their casting unlock. For exactly one, read its pinned progression row by explicit `level`; for multiple, retain existing weighted table; retain independent pact count/level. Do not infer table order. Reject missing/duplicate/malformed required rows and expose a bounded unavailable-slot status rather than inventing accepted mechanics. Independently challenge the compatibility policy for old pins before coding: full-caster fallback may be equivalent for supported SRD profiles, but custom/half/third data cannot be silently guessed. No SQL/content/dependency changes. Exit: pure boundary tests plus actual provider/UI agreement among slot tracker, cast options, rest and print. This child does not claim EK/AT support.
2. **R21.1b — per-class casting ability.** Resolve attack/DC from the spell's authenticated, pinned source profile rather than the global best. Keep sheet summary policy explicit; reuse existing effect ability logic. Test two classes with opposite ability strengths, the same spell acquired under each class, and unknown source. Feature fixed-DC/ability semantics remain unavailable until explicitly represented.
3. **R21.1c — pinned subclass profiles.** Add an additive typed subclass casting contract and pass only exact selected, readable subclass refs paired with their parent/class level. Resolve known/list/prepared and direct slot progression once for all consumers. Do not double-count a subclass as another class. Original third-caster fixtures must prove casting unlocks, single-source versus multiclass progression and spell controls; malformed/missing/mismatched parent/system/pins stay unavailable. No retroactive content rewrite or named EK/AT acceptance.
4. **R21.1d — selected-spell payment contract, then one feature at a time.** Design typed bindings containing controller feature pin, spell pin, class, unlock, eligibility, permitted cast level and payment/recovery. Use Arcanum first (one independently tracked long-rest use per unlocked choice), then Mastery (preparation/base-level/no-use plus explicit replacement), then Signature (two distinct choices, separate uses, prepared exemption). Add one feature-payment `CastChoice` through the existing effect/concentration/roll flow and conditional writer; consume use and apply effects in one patch. Reuse rest reset logic. Existing generic flags/counters are insufficient. Decide storage/provenance/copy behavior before implementation; any required migration gets its own reviewed scope, not an implicit part of this checkpoint.

## Pin, permission and mutation invariants

- [feature-refs-server.ts](../../lib/supabase/feature-refs-server.ts), lines 42–69 reconciles immutable feature manifests; [spells-server.ts](../../lib/supabase/spells-server.ts), lines 47–117 reconciles/reads captured grants. Reuse grant authority; never resolve current definitions by slug to repair a historical pin.
- Existing spell overlay (server helper lines 123–146) deliberately lets selected acquisition version take display precedence over a different grant version. Advanced free-cast bindings must choose an explicit exact-version policy; proposed default is binding the chosen spell version and refusing inconsistent eligibility. Do not silently reinterpret that logical overlay as a payment grant or change its current acquisition provenance.
- Preserve page owner/viewer separation (lines 50–57/115/153), view authorization in grant RPC lines 660–664, owner-only reconciliation with character lock lines 706–727, and historical content access policy in [feature-grant-integrity](../../supabase/migrations/20260720185127_feature_grant_integrity.sql), lines 80–125/179–258. Readable shared/campaign pins may have another owner; never require definition owner equals viewer. No anonymous/unrelated access or DM mutations.
- Derive eligibility from readable exact controller/spell pins and stored class choices, not a caller-supplied label, level or counter. Any future server write path revalidates that authority. Preserve confirmed-state conflict/uncertain handling, no automatic uncertain retry, duplicate roll receipt protection, and one atomic resource/effect/concentration write. No separate advanced feature state writer.

## Acceptance boundaries

For R21.1a, meaningful tests must cover half-caster levels 1/2/3/5/9, full-caster parity, original third progression, noncaster or Pact alongside one regular source, true two-source multiclass rounding, unordered/sparse/duplicate rows, missing pins, and pact count/level consistency. Preserve existing `computeCasterLevel` floor tests; [helpers tests](../../tests/spells/helpers.test.ts) currently lack `computeMaxSlots` coverage. Regression-test shipped Arcane Recovery and conditional short rest against the resulting slot limits.

Later children require actual provider/cast-dialog selection and payment coverage; class-level rather than character-level unlocks; base versus upcast; per-chosen-spell Signature exhaustion; Mastery unprepared/replacement; Arcanum independent levels; source/version edit, removal and copy/provenance; malformed/foreign pins; owner/DM/anonymous/unrelated roles; and concurrent cast/rest conflict or uncertain response with no double spend. Use bounded offline fixtures before any separately authorized database acceptance. Pure tests and renderer fixtures cannot establish live manifest, permission or provider parity. Parent coordinates full `npm.cmd run check`, build and browser gates after implementation; none ran for this docs-only inventory.
