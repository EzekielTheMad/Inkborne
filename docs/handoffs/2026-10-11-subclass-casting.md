## Implemented behavior

- `subclass.ts` adds optional casting profile fields without defaulting absence to null/false. Declared subclass config requires ability/type/focus/ritual; known counts require twenty tagged class-level positions; a selected casting row requires nine nonnegative finite integers. Prepared subclass profiles require an explicit bounded preparation rule. Existing flavor/text/legacy spell defaults remain outside casting evidence.
- The additive subclass grant validator preserves string, nested-string and shipped `{ level, spells }` tiers. Grants and legacy top-level spells are excluded from casting-profile markers. Grant-only sparse subclasses inherit the validated parent and need no subclass casting row at the current class level. The class grant validator, immutable grant RPC and SQL are unchanged.
- `effective-sources.ts` resolves one source under each selected parent identity from exact readable parent/subclass refs. It validates parent pairing, character/system/content/version/type/slug and selected numbered rows; rejects missing/ambiguous/partial/dual profiles; permits readable historical pins from other authors. Complete subclasses of explicitly noncasting parents supply the source; explicit inactive rows remain valid inactive states. A subclass never adds another class to weighted multiclass arithmetic.
- The prior slot validator/math moved unchanged to `slot-resolution.ts` to keep the pure graph acyclic. Direct single-source rows, weighted multiple regular sources, Pact pools, custom large counts and unavailable distinctions retain R21.1a behavior.
- The actual provider uses this graph for counts/preparation/list/slots and R21.1b acquisition-specific attack/DC/MOD. Parent `classData` still supplies HP/hit dice. Acquisition identity and loaded spell snapshot/effects remain authoritative; subclass pin changes invalidate old committed callbacks even with identical raw state. Unknown sources block add/cast/rest/print at existing execution guards and keep loaded spell details visible.
- Add/search filters the pinned source list and its own direct learning ceiling intersected with the declared list range. It saves acquisitions under the parent slug. Shared stronger slots remain usable for upcasting. Preparation toggles follow the acquisition's source rather than another prepared class.
- Recovery remains the existing feature/resource/rest implementation: list identity alone grants no Wizard levels or Recovery. Explicit pinned homebrew recovery feature class reskins retain their existing scaling and atomic rest patch. Global highest casting summary remains explicitly global; per-acquisition execution resolves its own ability.

No new query, schema migration, content backfill, authoring UI, school restriction grammar, named book text, free-cast payment, dependency or permission change. Generic prepared/ritual/CastChoice execution semantics remain the shipped UI/pure casting contract, without a new rules or authority rewrite.
