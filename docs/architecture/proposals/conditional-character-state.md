# Conditional character-state proposal (not applied)

The existing state RPC cannot reject stale snapshots. Read-only hosted pg_proc inspection on approved project etcaodglvcspcmwecyxq confirmed exactly patch_character_state(uuid,jsonb), returning void, SECURITY INVOKER, empty search_path, and UPDATE state = coalesce(state,'{}') || state_patch WHERE id = character_id. Local migration 00031 and generated database types agree. No expected-state/version argument or conditional overload exists. Prior ability concurrency used direct table UPDATE with choices/base_stats equality filters, not this RPC. A client pre-read followed by the old RPC would retain the race. Replacing the full state through direct table UPDATE would change the shallow-merge contract and expand scope.

## Reviewable deliverables

- [SQL proposal](conditional-character-state.sql): a separate patch_character_state_if_current RPC; raw whole-state compare under owner-filtered row lock; applied/conflict/missing plus resulting_state; existing SELECT/UPDATE RLS stays active. Missing and inaccessible disclose no state. No table/index/policy changes; the function/execute grant still require schema/permission approval.
- [Executable client contract](conditional-hp-client.ts): validates exactly one result, returns explicit conflict/missing/uncertain, and never retries damage/healing. No production imports, Supabase client or application wiring.
- [Deterministic contract tests](../../../tests/e2e/conditional-hp-proposal.test.ts): both damage orderings, stale healing after independent absolute edits, linked concentration patch merge, missing, commit-then-response-loss, and malformed results. These exercise a serialized in-memory model and client adapter, not SQL/PostgreSQL/RLS execution or actual UI concurrency.

Comparing the entire raw confirmed state is deliberately conservative: even a concurrent notes or temp-HP edit conflicts. It never discards that independent saved edit. Current HP actions can also reset death saves or change concentration/effects, so checking only two numeric fields would omit real dependencies. This adds no revision column, ledger, framework or derived-rule recalculation. SQL NULL state normalizes only to {}; expected snapshot must preserve absent JSON keys, explicit JSON null and unknown keys. Display fallbacks/derived HP maxima are not the raw expected state. JSONB equality is structural; key order does not matter. Numeric HP intent continues to be computed by current mechanics, not the proposal SQL. This comparison is not a revision/event sequence: it does not detect an ABA change back to identical state, or changed class/ability/content inputs outside state that alter derived HP maximum. Broader rule/input concurrency is outside this minimal proposal.

## Integration required after approval

1. Generate migration through the existing Supabase workflow after approval; test SQL on an approved isolated local database and run advisors. Regenerate database types. This file under docs is not a discoverable migration and was never applied.
2. Provider/writer must retain the exact confirmed raw state alongside optimistic display state. Capture it at the settled action boundary; never use normalized display state or a snapshot fetched after computing stale damage. Pass the complete captured snapshot with the HP-derived patch. Use returned canonical state after applied.
3. Route every HP-mutating flow through the conditional contract, including Damage/Heal, temporary HP, hit-die/rest healing and linked death-save/concentration updates. Inventory, narrative and worldbuilding integration remain separate. Legacy tabs and the old RPC/direct updates can still overwrite after a guarded write; partial client rollout cannot establish system-wide safety. Decide explicitly how to retire/guard old writers before making a universal cross-client claim.
4. On conflict, reject the action, remove its optimistic overlay, block new relative actions, and show a readable stale-state message. Preserve independent queued absolute drafts; drain confirmed writes and prevent old-generation callbacks from replacing reloaded state. Offer explicit reload/current-state recovery, reset provider generation, then require a new user action. router.refresh alone does not reset an existing useState provider. Do not silently replay the old amount, trigger concentration prompts, spend dice again or force serial-intent HP5.
5. Missing/inaccessible is a failed save, not successful zero-row update. Transport/malformed response is uncertain: retain uncertainty until explicit reload/readback; no retry fallback to the old RPC. State readback alone is not a general proof of action identity under arbitrary concurrency.
6. Hit-die roll insertion currently occurs separately before the state write. A rejected conditional state update could still leave a roll record; do not claim atomic hit-die recovery from this RPC. Durable receipt and combined roll/state transaction remain a separately scoped design. This proposal prevents the demonstrated HP stale overwrite only once all relevant writers use the contract.
